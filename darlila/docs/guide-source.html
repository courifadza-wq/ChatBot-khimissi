1 · Présentation du projet

Ce que fait la boutique, et ce qui la distingue.

Dar Lila est une boutique en ligne algérienne (parfums, cosmétiques, articles bébé) refondue à partir du site statique d'origine en une application moderne Laravel + Vue.js, avec une gestion commerciale complète et la commande finalisée via WhatsApp.

Boutique publique

  • Catalogue de 22 produits répartis en 8 catégories, bilingue français / arabe (RTL instantané)
  • Filtres par catégories, recherche instantanée FR/AR, fiches produit en modale
  • Panier persistant (localStorage) avec recommandations produits
  • Commande en 3 étapes : panier → coordonnées (58 wilayas) → confirmation
  • Commande enregistrée en base (prix recalculés côté serveur) puis récapitulatif pré-rempli sur WhatsApp avec référence DL-XXXXXX
  • Galerie photos avec visionneuse, avis clients, carte Google Maps, design fidèle à l'original (ivoire / or / indigo, séparateurs zellige)

Espace d'administration (/admin)

  • Authentification Laravel Sanctum (tokens Bearer, anti brute-force)
  • CRUD produits complet : noms FR/AR, prix, catégorie, slug auto, image par URL ou téléversement direct vers Bunny Storage, mise en vedette, activation
  • Suivi des commandes : statistiques, filtres, détail dépliable, statuts (nouvelle → confirmée → expédiée → livrée / annulée)

Services intégrés

  • Notification e-mail au vendeur à chaque commande (Markdown, file d'attente, repli sûr)
  • Mode maintenance : page d'attente élégante, admin préservé, retour automatique du site
  • CDN Bunny.net : cache des images + stockage direct depuis l'admin
  • Outil de déploiement SFTP/SSH vers Hostinger en une commande
Qualité vérifiée L'ensemble a été testé automatiquement (Playwright) : parcours d'achat complet, CRUD admin, uploads, bascule AR/RTL, mode maintenance, protection des routes — zéro erreur console.

6 · Procédures courantes

Installation, lancement, gestion quotidienne.

Installer le projet (local, MySQL)

# 1. Base de données (une fois) mysql -u root -p -e "CREATE DATABASE darlila CHARACTER SET utf8mb4;" # 2. Backend cd backend-laravel composer install cp .env.example .env # ajuster DB_* si besoin php artisan key:generate composer setup # migrations + seeders + storage:link # 3. Frontend (autre terminal) cd ../frontend-vue && npm install && npm run dev

Gérer la boutique au quotidien (vendeur)

  • Ajouter un produit : /admin → Produits → « + Nouveau produit » → remplir FR/AR, prix, catégorie, image (URL ou fichier → Bunny si configuré)
  • Masquer un produit : interrupteur « Actif » dans la liste — il disparaît immédiatement de la boutique
  • Traiter une commande : /admin/orders → consulter le détail, appeler le client (paiement à la livraison), faire évoluer le statut
  • E-mails : chaque commande envoie une notification à SELLER_EMAIL (avec MAIL_MAILER=log, les messages sont dans storage/logs/laravel.log)

Mettre la boutique en maintenance

# Sur le serveur (backend) : php artisan shop:down --message="Retour à 14h" --retry=600 # → page d'attente bilingue, admin PRESERVÉ, auto-retour dès shop:up php artisan shop:up # rouvrir la boutique

La page d'attente vérifie toutes les 20 secondes si la boutique est revenue et se recharge automatiquement. Un bouton WhatsApp permet au client de commander malgré tout.

Après toute modification du code

cd deploy && npm run deploy # rebuild + upload + migrations + caches

7 · Déploiement — Hostinger + Bunny.net

Mise en ligne complète en une commande grâce à l'outil deploy/.

Préparer Hostinger (une fois)

  • hPanel → Bases de données MySQL : créer base + utilisateur
  • hPanel → Avancé → Accès SSH : noter hôte / port / identifiants
  • Créer le sous-domaine api.votre-domaine.com (il hébergera Laravel)
  • Choisir le datacenter France (Paris) pour la meilleure latence vers l'Algérie

Configurer et lancer

cd deploy npm install # client SSH/SFTP cp deploy.config.example.json deploy.config.json # vos accès + MySQL + SMTP npm run dry-run # simulation : build + plan, rien n'est envoyé npm run deploy # déploiement réel

L'outil enchaîne : build du frontend (avec l'URL d'API de production) → upload SFTP du backend (public/ renommé public_html/, index.php compatible mutualisé) → upload du frontend + .htaccess SPA → composer install distant → écriture du .env production → migrations + seeders → storage:link + php artisan optimize → vérifications HTTP.

Activer Bunny.net (images & vidéos)

NiveauConfigurationUsage
1 · Pull zoneBUNNY_CDN_URL=https://…b-cdn.netCache des images serveur (zéro code)
2 · Storage natifBUNNY_STORAGE_ZONE / _KEY / _CDN_URLUpload direct depuis l'admin → edge mondial
3 · Streambunny.net → StreamVidéos produit / hero (player + transcodage inclus)

Coûts Bunny : CDN $0.01/Go (EU), stockage $0.01/Go/mois, minimum $1/mois — environ $1-3/mois pour Dar Lila. Les visiteurs algériens sont servis depuis les edge européens.

Architecture cible darlila.com → frontend statique (dist)  ·  api.darlila.com → Laravel  ·  darlila.b-cdn.net → médias  ·  cross-origin géré par le CORS déjà configuré (CORS_ALLOWED_ORIGINS).

8 · Sécurité, exploitation & dépannage

Checklist de mise en production et réponses aux incidents courants.

Checklist avant ouverture au public

Changer ADMIN_PASSWORD dans le .env puis php artisan db:seed --class=UserSeeder
Régénérer APP_KEY (php artisan key:generate) — invalide les données chiffrées
Vérifier APP_ENV=production et APP_DEBUG=false
HTTPS actif sur les deux domaines (Let's Encrypt gratuit chez Hostinger)
CORS_ALLOWED_ORIGINS=https://darlila.com uniquement
SMTP configuré (MAIL_MAILER=smtp) et e-mail de commande reçu en test
Sauvegardes quotidiennes Hostinger activées (incluses plan Unlimited)
Ne jamais versionner .env ni deploy.config.json

Dépannage rapide

SymptômeSolution
